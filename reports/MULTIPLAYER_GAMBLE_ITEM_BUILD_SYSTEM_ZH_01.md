# Multiplayer Gamble Roguelike — 道具與構築系統草案 01

- 狀態：**設計草案；未經模擬、真人試玩或實作核准。**
- 分支：`multiplayer-gamble-engine-discovery-01`
- 目標：為賭局遊戲庫建立可辨識的 Roguelike 構築層，而不是替下注加上零散百分比。
- 範圍：道具規則、欄位、稀有度、取得／移除、協同、詛咒、消耗品與驗收條件。
- 貨幣：只使用 run 內虛擬籌碼；本文件不引入現金、現金兌換或玩家自由轉帳。
- 所有效果均為原型暫定規則。數字不是已驗證的平衡值。

## 1. 設計目標

道具應讓玩家逐步形成「這一趟我打算怎麼玩」的構築。理想的 run 結束時，玩家能用一句話描述自己的構築，例如：

- 「我靠安全收手累積利息，遇到大獎機會才把保留的籌碼押上去。」
- 「我會把詛咒轉成籌碼，但每次轉換都會留下新的麻煩。」
- 「我在多人分池中願意先合作，因為背叛者會替我充能。」
- 「我借未來的資源賭現在，靠減債道具避免 run 被追債拖垮。」

### 必須遵守的原則
1. **道具改變決策，不只改數字。** 優先設計改變規則、資訊、風險承擔或資源用途的效果。
2. **強力效果要有可理解的代價。** 代價可以是失去選擇、增加詛咒、鎖定籌碼、延遲負債或只限一次使用。
3. **協同應該可被玩家看懂。** 不依賴隱藏乘數或多層觸發堆疊。
4. **保留輸贏波動。** 道具可以降低某種風險，但不應把整個遊戲庫變成可預測的穩定收益機器。
5. **不把必須一起玩的隊友變成資源。** 多人道具不能逼玩家長期羞辱、排擠或懲罰特定真人。
6. **公開機率，不製造假資訊。** 道具可以揭露資訊或改變真實機率，但效果必須在下注前說明。
7. **每個效果都有上限與觸發時機。** 同一觸發不可無限遞迴；同一場遊戲內的觸發順序要固定。
8. **道具不應成為修補壞規則的藉口。** 若某遊戲沒有道具時不成立，應先修遊戲本身。

## 2. 構築基本規則

### 2.1 道具槽與持有上限
- 每位玩家／隊伍每個 run 初始有 **3 個常駐道具槽**。
- 可透過稀有事件或特定道具擴充，原型上限為 **5 槽**。
- 消耗品另有 **2 個消耗品槽**，不佔常駐道具槽。
- 道具效果除非明確寫明「可疊加」，否則同名效果不疊加；取得重複道具時可選擇回收成小額籌碼或刷新一次性充能。
- 道具被移除、替換或消耗時，相關持續效果即時結束；已經結算的效果不回溯。

### 2.2 稀有度與取得
| 稀有度 | 建議權重 | 定位 |
|---|---:|---|
| 普通 | 60% | 建立基本方向，效果單純 |
| 稀有 | 27% | 改變特定遊戲或資源決策 |
| 傳奇 | 10% | 定義構築玩法，通常帶明顯限制 |
| 禁忌 | 3% | 高風險、高影響力，常帶詛咒或不可逆代價 |

以上權重是商店／事件獎勵的初始候選值，不代表每個來源都使用同一抽取表。禁忌道具應讓玩家先看到完整代價，再確認是否取得。

### 2.3 取得、替換與回收
- 一般勝利、事件、商店、Boss 或特殊賭局可提供道具；不能每場勝利都固定掉落，否則構築很快失去取捨。
- 道具獎勵通常提供 3 選 1，讓玩家按現有構築做選擇。
- 槽位滿時，玩家必須選擇保留舊道具或替換，不可默默丟掉。
- 普通道具回收可得 15 籌碼、稀有 30、傳奇 50；禁忌道具不可直接賣掉，需透過淨化事件或支付明示代價移除。
- 回收價格是暫定值，後續要檢查它是否成為「拿到不想要的道具就固定賣掉」的最佳選擇。

### 2.4 效果結算順序
每場賭局固定按以下順序處理：
1. 顯示遊戲規則、機率、下注額與債務／詛咒狀態。
2. 選擇是否啟動消耗品。
3. 啟動下注前道具與選擇型效果。
4. 玩家下注並鎖定籌碼。
5. 執行遊戲本身的選擇與隨機結果。
6. 結算原始遊戲結果。
7. 觸發「勝利／失敗／收手／爆掉」道具。
8. 處理詛咒、債務、利息與延遲效果。
9. 發放事件獎勵，檢查道具槽與 run 結束條件。

若兩件道具同時觸發，按玩家取得順序由左至右處理；若效果改變同一數值，除非明確寫明乘算，否則採加法並受上限約束。任何效果不得重新觸發自身。

## 3. 道具分類

### A. 資源與經濟
讓玩家管理現有籌碼、鎖定獎金、借款與回收。

### B. 賭局規則改造
讓特定類型賭局出現新的選擇、保護或風險。

### C. 資訊與控制
揭露部分隱藏資訊、提供一次重擲或在結果揭曉前改變選擇。

### D. 風險轉換與詛咒利用
把失敗、債務或詛咒轉成另一種資源，但不能讓代價消失得毫無限制。

### E. 多人互動
改變合作、背叛、公共獎池或同步選擇，不直接控制別人的輸入。

### F. 消耗品
單次使用的高影響效果；取得時要決定是否為它保留有限槽位。

# 4. 道具目錄：第一批 24 件

以下為第一批道具候選。每件道具都提供中文名稱、稀有度、效果、限制與設計目的。效果暫定，未經測試。

## A. 資源與經濟

### 1. 銅製存錢罐
- 稀有度：普通
- 效果：每次完成賭局並選擇收手，額外獲得 5 籌碼；每個賭局最多觸發一次。
- 限制：爆掉或直接失去下注的回合不觸發。
- 設計目的：獎勵保守累積，但小額固定收益不應取代高風險選擇。

### 2. 複利帳本
- 稀有度：稀有
- 效果：每經過 3 場已結算賭局，若這三場至少有兩場收手領取正數總返還，獲得 20 籌碼。
- 限制：每個 run 最多觸發 3 次；不計入只領到 0 的結果。
- 設計目的：建立以穩定收手為核心的構築。需要檢查是否鼓勵只玩最低風險遊戲。

### 3. 破產保險箱
- 稀有度：稀有
- 效果：每個 run 第一次因賭局失去全部可用籌碼時，保留 1 籌碼並獲得「破產」標記；之後不能再次觸發。
- 限制：不免除債務、詛咒或未結清費用。
- 設計目的：給瀕死 run 一次繼續玩的機會，但不直接補發一大筆錢。

### 4. 當鋪契約
- 稀有度：普通
- 效果：可在商店把一件常駐道具賣出，額外獲得 10 籌碼；下一次道具獎勵少一個可選選項。
- 限制：每個商店只能使用一次。
- 設計目的：把短期資金換成未來選擇品質的損失。

## B. 賭局規則改造

### 5. 第二枚硬幣
- 稀有度：普通
- 效果：在 Coin Call 中，下注前可選擇擲兩次硬幣並取較差結果，或支付 10 籌碼取較好結果。
- 限制：每場 Coin Call 只能選一種模式；若選取較好結果，10 籌碼無論結果如何都支付。
- 設計目的：明確的風險／成本選擇。正式規則需定義「取較好／較差」是指猜測命中與否，不是事後挑選任意結果。

### 6. 金庫撬棍
- 稀有度：稀有
- 效果：Vault Ladder 每次成功後，可選擇把當前可收手總返還額提高 25%，但下一階成功率降低 10 個百分點。
- 限制：每場最多使用一次；成功率最低為 5%；增加的返還只在本回合，不能永久複製。
- 設計目的：以當下更高獎金換取更難的下一階。

### 7. 探雷針
- 稀有度：稀有
- 效果：Minefield 每場可免費查看一格是否有雷，不會翻開該格。
- 限制：不能查看已翻開格；每場一次；若所有剩餘格都已知則不能使用。
- 設計目的：提供真實資訊，但不直接保證安全。需要驗證它是否讓 Minefield 過於容易。

### 8. 偏心輪軸
- 稀有度：稀有
- 效果：Three-Reel Relics 開始前，選擇一個輪軸，將其中一個符號的出現權重提高；同時將另一個符號的權重降低。
- 限制：具體符號權重必須在旋轉前顯示；不能將任何結果機率改成 0 或 100%；每場一次。
- 設計目的：讓拉霸玩家選擇風險輪軸，而不是單純按下按鈕。

### 9. 讀牌手套
- 稀有度：普通
- 效果：Card Duel 每場第一次猜測前，可查看下一張牌的顏色（紅／黑），但看不到點數。
- 限制：只提供顏色資訊；若規則使用的牌組不是標準四色牌，需提供等價的公開資訊。
- 設計目的：提供局部資訊，不讓猜測變成確定答案。

## C. 資訊與控制

### 10. 退路籌碼
- 稀有度：普通
- 效果：每個 run 一次，在尚未鎖定獎金的連續挑戰中，失敗時可保留下注額的 50%（向下取整）作為總返還。
- 限制：不能用於 Jackpot Draw、Pot Split 或已經結算的賭局；啟動後消耗。
- 設計目的：一次性減少災難性損失，但不保護全部獎金。

### 11. 重擲骰骨
- 稀有度：普通
- 效果：在使用骰子的遊戲中，看到骰子結果後可重擲其中一顆骰子一次。
- 限制：每個 run 一次；若遊戲規則要求下注前宣告重擲，此道具不能在結果揭曉後使用，需以遊戲公平性規則為準。
- 設計目的：提供局部控制。使用前必須確認不會與該遊戲既有重擲規則衝突。

### 12. 封存信封
- 稀有度：稀有
- 效果：下注前支付 15 籌碼，將本場下注額的一半封存；若賭局失敗，封存部分退回；若勝利，封存部分不計入任何賠付倍率。
- 限制：向下取整；不適用於 Debt Collector 借款額，也不影響公共獎池的其他玩家貢獻。
- 設計目的：以確定成本換取部分保本，但降低成功時的獎金。需要檢查是否成為低風險固定最佳選擇。

### 13. 先知的裂鏡
- 稀有度：傳奇
- 效果：每個 run 一次，在下注前查看本場隨機結果池中一個真實的機率摘要，例如「爆掉結果佔 55%」；不能得知即將抽出的確切結果。
- 限制：不能用於玩家同時秘密選擇的 Pot Split，也不能揭露其他玩家的私密選擇。
- 設計目的：提升對風險的理解，而不是偷看未來。

## D. 風險轉換與詛咒利用

### 14. 黑曜石籌碼
- 稀有度：稀有
- 效果：每個 run 第一次獲得詛咒時，可選擇保留詛咒並獲得 40 籌碼，或拒絕獎金並阻止該詛咒。
- 限制：每個 run 一次；不適用於直接導致 run 結束的效果。
- 設計目的：把詛咒轉成有代價的經濟選擇。

### 15. 罪債天平
- 稀有度：傳奇
- 效果：每個 run 一次，將一個詛咒轉換為一筆債務：立即獲得 80 籌碼，兩場已結算遊戲後需償還 120。
- 限制：若已有未清債務，不能啟動；詛咒被移除後不可再用同一詛咒觸發其他效果。
- 設計目的：把一種延遲代價換成另一種延遲代價，不是免費清除負面效果。

### 16. 破碎王冠
- 稀有度：禁忌
- 效果：每場賭局第一次爆掉時，獲得 60 籌碼。
- 代價：每次觸發後永久增加一層「王冠裂痕」；每層使下一場賭局的下注上限降低 10%，最多 3 層。第三層後道具破碎並消失。
- 設計目的：鼓勵玩家利用失敗換取短期資金，但連續失敗會逐步限制選擇。
- 風險：若 60 籌碼足以讓玩家刻意反覆爆掉套利，需降低獎勵或改成只觸發一次。

### 17. 逆命印章
- 稀有度：傳奇
- 效果：每個 run 一次，將一個本來會造成籌碼損失的結果轉成「不損失籌碼，但獲得一個詛咒」。
- 限制：不改變 Pot Split 的其他玩家結算、不免除到期債務、不阻止直接的 run 結束事件。
- 設計目的：讓玩家決定是否願意把立即損失換成長期麻煩。

## E. 多人互動

### 18. 信任徽章
- 稀有度：普通
- 效果：在 Pot Split 選擇合作且至少另一名玩家也合作時，獲得 10 籌碼。
- 限制：每場一次；不能因同一場多人重複觸發；若只有自己合作，不發獎勵。
- 設計目的：讓合作構築有明確收益，但避免合作永遠是唯一正解。

### 19. 背叛者的印記
- 稀有度：稀有
- 效果：Pot Split 中若至少一人選擇獨吞，且你選擇合作，獲得一枚「怨氣」；集滿兩枚可在商店換取一件普通道具。
- 限制：每場最多獲得一枚；若全員合作則不觸發；怨氣不跨 run 保存。
- 設計目的：讓被背叛者有後續構築方向，而非只留下挫折。
- 風險：不能讓合作成為故意等待別人背叛的固定刷資源策略。

### 20. 公共金庫鑰匙
- 稀有度：傳奇
- 效果：在多人共享獎池遊戲中，可選擇將自己原本可領取的獎勵延後鎖入公共金庫；若下一場共享獎池遊戲至少兩人合作，金庫額外增加 50%。
- 限制：每個 run 一次；若下一場沒有觸發條件，延後的獎勵仍返還給原持有人，但不獲得額外增幅。
- 設計目的：把個人短期收益轉成團隊風險與未來收益。

## F. 消耗品

### 21. 玻璃骰
- 稀有度：消耗品
- 效果：在任何一場使用公平骰子的賭局中，擲出後可重擲一次；重擲結果必須採用。
- 限制：使用後消耗；不能用於玩家私密選擇或抽牌結果。
- 設計目的：一次性高張力控制，不允許反覆刷到滿意為止。

### 22. 緊急提款單
- 稀有度：消耗品
- 效果：立即獲得 50 籌碼。
- 代價：下一次商店價格提高 25%；若 run 中沒有後續商店，代價不觸發。
- 設計目的：簡單直接的緊急資源，代價延後但可預期。

### 23. 詛咒封蠟
- 稀有度：消耗品
- 效果：移除一個普通詛咒。
- 代價：支付 20 籌碼；若籌碼不足，不能使用。
- 限制：不能移除禁忌道具自身的專屬代價或未清債務。
- 設計目的：讓負面狀態可管理，但不能把所有風險都洗掉。

### 24. 命運收據
- 稀有度：消耗品
- 效果：在抽取道具獎勵時，查看全部選項後可重抽一次整組選項。
- 代價：重抽後必須從新的一組選擇，不可回頭挑選第一組。
- 限制：每次道具獎勵最多使用一張。
- 設計目的：避免壞選項卡死構築，但仍讓重抽具有真實風險。

# 5. 初步構築範例

這些是用來檢查道具是否能形成不同玩法的設計假設，不是已驗證的最佳流派。

## 構築 A：穩健收手
- 銅製存錢罐
- 複利帳本
- 封存信封

**玩法：** 選擇能夠合理收手的遊戲，累積多次小額收益，封存信封則降低一次災難性損失。弱點是爆發力低，可能無法應對時間或籌碼壓力。

**必測漏洞：** 玩家是否永遠只玩最低風險賭局，導致其他遊戲失去存在價值。

## 構築 B：貪婪階梯
- 金庫撬棍
- 退路籌碼
- 逆命印章

**玩法：** 追逐高階獎金，用一次性保護承擔更大的推進風險；失敗時可將立即損失換成詛咒。

**弱點：** 道具用完後風險很高，且詛咒可能壓縮後續下注能力。

**必測漏洞：** 退路籌碼與逆命印章不能對同一次失敗重複觸發，把本來的全失變成免費通關。

## 構築 C：詛咒套利
- 黑曜石籌碼
- 罪債天平
- 破碎王冠

**玩法：** 主動把負面狀態轉成短期籌碼，換取急需的資源。

**弱點：** 債務與下注上限會逐步限制未來選擇；若 run 太短，延遲代價可能看起來像免費資金，因此需按剩餘關卡數驗證。

**必測漏洞：** 不得刻意刷詛咒、爆掉或重開 run 來取得無限籌碼。

## 構築 D：合作反擊
- 信任徽章
- 背叛者的印記
- 公共金庫鑰匙

**玩法：** 願意合作時獲得穩定小收益，被背叛後轉成後續道具資源，並可把一部分收益延後投入公共金庫。

**弱點：** 過度依賴其他真人的選擇，單人或低人數時價值會下降。

**必測漏洞：** 不得鼓勵玩家透過帳號配合、固定輪流背叛或房間外協議製造無風險收益。

# 6. 詛咒與負面道具原則

詛咒不是單純的「道具反面」，而是讓構築變得更尖銳的代價。建議第一批只做 6 種，先確認玩家理解與承受方式。

| 詛咒 | 效果草案 | 可能的構築用途 |
|---|---|---|
| 裂錢袋 | 每次賭局結算後，若總返還為 0，額外失去 5 籌碼 | 可被破產保險箱或逆命印章緩解 |
| 沉重利息 | 每場結算後，未清債務增加 10，最多增加 30 | 配合減債／清債選擇，但不應與其他利息無限乘算 |
| 猶豫印記 | 每場賭局開始時，必須先鎖定下注額，不能在查看額外提示後更改 | 對抗依賴資訊的構築 |
| 壞運迴聲 | 每個 run 第一次爆掉後，下一場不能使用消耗品 | 限制過度依賴一次性保護 |
| 鐵手銬 | 道具槽暫時少一格，直到支付 40 籌碼或完成指定事件 | 造成有選擇的短期壓力 |
| 貪婪烙印 | 若連續兩次選擇繼續挑戰，下一次失敗額外獲得一個普通詛咒 | 對推進型構築施加代價 |

### 詛咒規則
- 詛咒效果必須在取得前完整顯示。
- 同名詛咒預設不疊加；若需要疊加，必須明確標示層數上限。
- 清除詛咒不會自動清除由詛咒產生的債務，除非效果明確寫出。
- 不可讓詛咒把玩家永久鎖死在無法下注、無法收手或無法完成 run 的狀態。
- 禁忌道具的專屬代價不能用普通消耗品輕易清除，否則玩家只會把它當成免費強化。

# 7. 與賭局遊戲的相容規則

道具效果必須按遊戲類型分類，不要為每一款遊戲獨立堆出一套互不相容的規則。

| 遊戲類型 | 合理的道具介入 | 禁止或需特別審查 |
|---|---|---|
| 單次抽籤／輪盤 | 改變下注成本、揭露機率摘要、一次性重抽整組結果選項 | 看到確切結果後任意改結果 |
| 連續挑戰／收手型 | 保護部分下注、改變下一階風險、鎖定一部分獎金 | 多件道具對同一次失敗重複保護 |
| 隱藏格／隱藏牌 | 查看有限真實資訊、一次重擲或改變選擇順序 | 宣稱純隨機未揭露格子有規律 |
| 骰子／競速 | 有上限的重擲、公開改變權重或一次性干預 | 結果揭曉後無成本反覆重擲 |
| 多人共享池 | 合作獎勵、背叛後補償、延後投入公共金庫 | 替其他玩家做決策、強迫公開私密選擇 |
| 債務／資源管理 | 延期、減債、用詛咒換資源 | 無上限借新還舊、重開 run 清除債務 |

## 觸發防護
1. 同一個遊戲事件每件道具最多觸發一次，除非明確寫明不同次數。
2. 「獲得籌碼」觸發不能再觸發另一個「獲得籌碼」效果，除非第二件道具明確只監聽原始賭局結算。
3. 退路籌碼、逆命印章等失敗保護對同一回合只能有一種生效；玩家須在結果結算前按固定順序選擇或依明確優先序處理。
4. 道具不得改寫已結算的歷史紀錄或反覆重新觸發自己。
5. 若玩家在效果觸發時離線，效果仍按伺服器記錄的既定順序完成；此為未來實作需求，目前尚未實作。

# 8. 道具取得節奏草案

以 8 個主要節點的短 run 為例，提供選擇而不是每關都塞獎勵：

| 節點 | 候選獎勵 |
|---|---|
| 起始 | 從 3 件普通道具選 1 件，或選擇不拿道具取得 20 籌碼 |
| 第 1 個事件 | 小額籌碼、普通道具或清除普通詛咒，三選一 |
| 第 2 個賭局 | 無保證掉落；依結果與事件表判定 |
| 第 3 個商店 | 購買、回收、移除普通道具或購買消耗品 |
| 中段精英事件 | 稀有道具三選一，或接受禁忌道具及其完整代價 |
| 第 5–6 節點 | 隨機事件、債務處理或道具協同事件 |
| 最終挑戰前 | 一次補給／消耗品選擇，但不能免費重組整個構築 |
| 最終挑戰後 | 結算 run；除非設計明確有跨 run 解鎖，不保留本 run 籌碼或債務 |

這只是節奏假設。正式節點數、獎勵頻率與商店價格應等賭局規則和道具效果通過檢查後再決定。

# 9. 道具系統驗收門檻

進入實作前至少要完成以下工作：

### 規則與數學
- [ ] 每件道具的觸發時機、使用次數、消耗方式、上限與失效條件明確。
- [ ] 每件道具都能用一個最小例子手算結算。
- [ ] 同一事件不會被多件道具重複保護或無限觸發。
- [ ] 沒有無成本的籌碼生成、債務洗除、重開套利或無限重擲。
- [ ] 主要構築的收益分布、極端損失與失敗後續都有紀錄。

### 遊戲體驗
- [ ] 至少有 4 種策略方向，不是所有構築都追求同一種最佳玩法。
- [ ] 普通道具單獨有用，稀有／傳奇道具能改變決策，但不保證勝利。
- [ ] 每件道具都能說明「它讓玩家做出什麼原本不會做的選擇」。
- [ ] 真人試玩有記錄：選擇理由、規則理解、後悔點、覺得無聊的回合、道具組合是否過強。
- [ ] 不把模擬的勝率或 EV 當成趣味性的替代指標。

### 工程與安全
- [ ] 道具效果可用明確的事件類型與固定結算順序表示，不靠隨機程式碼插入任意副作用。
- [ ] 多人模式下，私密選擇不會被道具洩漏；結算不依賴客戶端自行宣告的獎勵。
- [ ] 每場遊戲可重現其道具觸發紀錄，便於調查結算爭議。
- [ ] 正式實作前完成設計核准；本文件本身不授權開始伺服器、UI、資料庫或產品程式碼工作。

# 10. 未解問題與下一步

1. **個人道具還是團隊共用道具？** 本草案預設道具屬於玩家／隊伍中的單一構築持有人，但多人 run 需決定是否每人各自持有 3 槽，或整隊共享 3 槽。兩者的策略完全不同，不能到實作時才決定。
2. **玩家是否可以交換道具？** 第一版建議不允許玩家自由交易道具，避免固定分工、協同刷資源與複雜的所有權爭議。
3. **死亡／破產後是否重建構築？** 建議 run 內可以因事件失去道具，但不能在沒有代價下重設所有槽位。
4. **是否有跨 run 永久解鎖？** 第一版先不加入永久數值成長；可解鎖新道具種類，但不要讓老玩家單純因累積永久加成碾壓新玩家。
5. **道具總量是否足夠？** 24 件是第一批候選，不是最終內容量。應先驗證 4 種以上構築是否真的成立，再擴充道具數量。

## 建議下一階段
1. 先確定多人遊戲中道具是「每位玩家持有」還是「整隊共用」，再鎖定持有上限與交易規則。
2. 逐件審查 24 件道具的歧義、無限觸發、經濟漏洞與相容遊戲。
3. 建立可重現的道具效果靜態檢查與小型模擬，優先找出資源生成循環、保護效果疊加、必選道具與無效道具。
4. 用紙上試玩驗證至少四種構築方向，再擴充道具池。
5. 在設計門檻與真人試玩完成前，不開始正式遊戲程式實作。
