# Multiplayer Gamble Roguelike — 極端構築與無限循環設計原則 01

- 狀態：設計方向已由專案負責人明確提出；本文件將其轉成後續設計與驗收原則。
- 分支：`multiplayer-gamble-engine-discovery-01`
- 範圍：Roguelike 道具、賭局、事件、資源循環、稀有組合與無限／近乎無限構築。
- 不包含：任何正式 AMQ 產品程式碼、伺服器、UI、資料庫或既有多人模式變更。
- 驗證狀態：設計規則；尚未經模擬、真人紙上試玩或實作驗收。

## 1. 核心方向

**不追求每局接近相同的成果；追求每局都有值得追逐的可能性。**

肉鴿的高價值體驗之一，是玩家從隨機取得的道具、賭局、事件與代價中，拼出單件道具看起來普通、組合後卻極端強大的構築。某些 run 可以普通、失敗或災難性地結束；少數 run 應該可能出現大獎、逆轉、失控成長，甚至近乎無限的資源循環。

不能為了讓數據整齊，就把所有極端結果削成平均值。平衡不是讓每個構築一樣強，而是確保不同選擇仍有情境價值，並且極端強度有足夠的取得難度、可理解的成因與值得承擔的風險。

## 2. 「無限」的三種不同問題

1. **理論上可構成：** 道具、事件、賭局或資源轉換在規則上形成循環，可能產生無上限次數或收益。
2. **實際上能否組成：** 玩家需要多少特定道具、稀有事件、順序、資源、代價與運氣，才能啟動循環。
3. **能否兌現為收益：** run 的剩餘節點、每回合觸發上限、可下注資金、結算時機、債務、對手互動或終局規則，是否允許玩家把循環轉成真正的巨大成果。

這三件事必須分開檢查。發現理論上的無限循環，不等於必須刪除它；應先確認它的組成難度、可讀性、兌現窗口與遊戲影響。

## 3. 無限構築處理政策

### 預設保留

- 不因為構築「太強」或理論上可以無限，就自動削弱或移除。
- 允許多件道具形成超線性協同，包含乘算、連鎖觸發、成本回收、風險轉換與罕見的資源循環。
- 可以讓低機率的組合產生遠高於一般 run 的收益；不要求各構築的期望值或通關率相近。
- 允許玩家為追逐特定組合而改變選路、保留資源、承受詛咒或放棄眼前的小收益。

### 必須檢查，而不是一律禁止

- 循環是否真的能在有限 run 內重複觸發。
- 玩家是否需要承擔可見且有意義的前置成本或失敗風險。
- 觸發上限是否只是技術性限制，卻把原本應有的爽感切斷；若要設上限，需確認它服務的是遊戲節奏或多人互動，而非單純壓低數值。
- 組合是否能讓所有其他遊戲、道具與決策都變成毫無意義的必選答案。
- 多人環境中，是否把隊友的退出、斷線、私密選擇或刻意配合變成可無風險套利的工具。
- 循環是否跨越 run 重置、債務到期、道具替換或結算邊界，意外複製資源或逃避代價。

### 修正優先順序

若發現問題，依序考慮：
1. 保留核心協同，只修正含糊的觸發時機或重複結算。
2. 把無限收益變成需要持續承擔風險、投入資源或面對終局的循環。
3. 讓組合極難完成、但完成後仍有足夠強度。
4. 限制它在特定條件下的兌現，而不是直接刪除構築。
5. 只有在它破壞核心決策、多人公平底線或可重現的規則正確性時，才考慮移除或大幅重做。

## 4. 構築價值不等於平均收益

設計與報告不得只用平均籌碼、平均通關率或單一 EV 分數判斷道具。至少分別觀察：

- **普通 run：** 是否仍有選擇、風險與可辨識的玩法。
- **協同 run：** 玩家能否發現並追逐有方向性的構築。
- **爆發 run：** 罕見組合是否能帶來明顯的力量躍升。
- **極端 run：** 是否可能出現大獎、災難、逆轉或近乎無限的循環。
- **追逐成本：** 為了拿到極端組合，玩家犧牲了什麼、承擔了什麼。
- **選擇退化：** 組合完成後，是否仍有需要判斷的事情，或所有選擇都已變成無腦重複。
- **重玩動機：** 玩家是否會因為看見尚未完成的構築可能性，而自願再開一局。

這些是需要由規則分析、模擬與真人試玩分別提供證據的問題，不是可由模擬直接證明的樂趣指標。

## 5. 稀有強力組合的設計要求

- 單件道具可以普通，組合後可以極端強大。
- 協同應可理解、可被玩家發現，最好能從道具文字、遊戲狀態或事件提示看出線索。
- 不要求每局都能完成同一套構築；可用不同稀有度、路線與風險代價控制取得難度。
- 道具池不能只提供數值升級，必須有能改變玩家行為的效果。
- 可以設計互相矛盾或需要取捨的構築方向，讓玩家因早期取得的道具而改變目標。
- 不要為了讓每件道具在所有 run 都有用，就把它們設計成平淡的通用加成。
- 稀有度本身不應是唯一的限制；取得時機、組合需求、資源成本、觸發條件與負面代價都可形成門檻。

## 6. 後續驗收方式

### 規則與靜態檢查
- 明確列出每個觸發事件的先後順序、每次觸發上限與結算邊界。
- 找出能否循環產生籌碼、重複觸發獎勵、免除成本、反覆重置或延後債務。
- 將「合法的極端協同」與「不符合規則的重複結算」分開記錄。

### 可重現模擬
- 尋找低機率、高回報組合的出現率與收益分布。
- 記錄尾端結果、極端收益、災難性損失與完成構築所需的條件。
- 比較有／無特定道具組合時的決策和資源變化。
- 不以拉平 EV、平均收益或通關率作為自動修正目標。
- 模擬用來查找漏洞與理解分布，不能證明好玩。

### 真人紙上試玩
- 記錄玩家是否主動追逐某個組合、是否理解協同、是否願意為它放棄眼前收益。
- 記錄普通 run 是否仍有趣，以及極端 run 是否真的帶來驚喜、成就感或「下次我還要試」的動機。
- 若玩家只是在等待隨機發牌、無法影響構築追逐，應改善可見線索與選擇，而不是只調高稀有度。
- 未進行真人試玩前，不得宣稱已證明重玩性或樂趣。

## 7. 對目前 24 件候選道具的直接影響

- 不能因「破碎王冠」「罪債天平」或其他道具可能與別件道具形成高收益，就先把它們判為錯誤設計。
- 檢查破碎王冠時，必須區分「刻意選擇高風險、用爆掉換取短期籌碼」與「無成本、可反覆重置的資源漏洞」。
- 檢查退路籌碼、逆命印章與封存信封時，先確認同一次損失的觸發順序，再判斷它們能否組成強力保護構築；不可預設所有保護組合都必須被禁止。
- 檢查罪債天平、沉重利息與其他經濟道具時，允許玩家建立高風險債務構築，但要確認代價何時到期、是否能無限借新還舊，以及剩餘 run 節點是否讓延遲成本失去意義。
- 後續新增道具應刻意探索會與既有道具產生非線性協同的效果，而不只是平均分布的單件增益。

## 8. 本文件的決策摘要

**設計目標不是消滅無限，而是控制玩家組成、啟動與兌現無限的途徑，同時保留罕見、極端、值得追逐的構築。**

凡是後續模擬報告提出「此組合過強」時，必須附上具體證據：取得條件、實際觸發路徑、run 內可兌現收益、對其他決策的影響，以及是否存在可行的最小修正。單獨一句「不平衡」不是充分理由。
